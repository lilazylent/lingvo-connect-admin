ТЗ: Lingvo Connect CRM — Final MVP Frontend Polish v4
1. Главная цель
Довести текущую CRM не до состояния «похоже на референс», а до состояния готового клиентского MVP, который можно открыть Олегу и не объяснять, почему какой-то экран ещё временный.
У нас теперь три источника истины:
№1 — утверждённый master-reference CRM. Он определяет геометрию, плотность, карточки, таблицы, sidebar, topbar, радиусы, светлую тему и общую композицию.
№2 — реальный сайт Lingvo Connect. Он определяет характер бренда: тёплый светлый фон, винно-бордовый акцент, тёмный navy, строгая типографика, тонкие линии, чистая редакционная композиция.
№3 — существующий backend CRM. Он определяет функциональность и реальные данные. Никаких выдуманных рейтингов, процентов, уведомлений, KPI или кнопок ради красивой картинки.
Что сейчас сделано неправильно
2. Текущий v3 только частично повторяет master-reference
Shell уже пошёл в правильном направлении, но многие страницы по сути остались старыми компонентами, переодетыми CSS.
Это особенно видно на:
- Клиентах;
- Исполнителях;
- Файлах;
- карточке заказа;
- формах редактирования;
- части Настроек.
Именно поэтому Dashboard относительно похож, а дальше ощущение единой CRM теряется.
Решение: не добавлять ещё один огромный stylesheet поверх legacy. Для ключевых рабочих страниц пересобрать композицию самих React-компонентов.
3. Масштаб и плотность интерфейса
На твоём 1920×1080 текущий интерфейс местами выглядит слишком мелким и растянутым.
Особенно:
- таблицы;
- labels;
- secondary text;
- строки списка;
- подписи KPI;
- фильтры;
- некоторые кнопки.
В коде я нашёл много размеров уровня:
9.5px
10px
10.5px
11px
11.5px
Для основной рабочей CRM это перебор.
Буду менять систему типографики
Базовый UI-текст: примерно 13–14 px.
Основной текст таблиц: 12.5–13.5 px.
Labels/secondary: 11.5–12.5 px, только действительно вспомогательные элементы могут быть мельче.
Page title сохраняем крупным и выразительным.
И одновременно ограничиваем растягивание контента на сверхшироком desktop, чтобы карточка заказа не превращалась в огромный пустой лист шириной полтора метра.
4. Sidebar
Текущая структура правильная, но доведу её до референса.
Будет:
- правильная ширина;
- стабильная геометрия nav-item;
- одинаковые icon box;
- более точное active state;
- правильный логотип;
- аккуратная нижняя бренд-карточка.
Сейчас нижний promo и mountain banner фактически сделаны через готовые картинки, в которые уже запечён текст, а поверх них компонент снова пытается рисовать текст.
Это неправильная архитектура.
Переделаю:
asset = только изображение
text = настоящий HTML
decorations = CSS
Так они будут нормально работать и в responsive, и в dark, и при zoom.
5. Topbar
Привести максимально близко к master-reference:
- размеры поиска;
- положение controls;
- профиль;
- avatar;
- spacing;
- separator;
- sticky behavior.
И я уже нашёл конкретный баг в текущем v3.
В отчёте было заявлено:
fake notification dot удалён

Но в CSS сейчас всё ещё существует:
.lc-notification-button::after
который безусловно рисует красную точку.
Это будет удалено. Уведомление появляется только при наличии настоящего состояния/API.
6. Dashboard
Это сейчас самая близкая к референсу страница, поэтому её не надо заново изобретать.
Нужно довести:
- точную высоту metric cards;
- padding;
- typography;
- ширину finance strip;
- spacing между блоками;
- quick actions;
- таблицы;
- server/system card;
- banner.
На видео mountain banner практически выглядит пустым — это исправлю.
То же самое с растением в sidebar.
Dashboard станет эталонной страницей, относительно которой будут сверяться остальные модули.

рабочая зона:

Сейчас некоторые варианты страницы выглядят либо слишком пустыми, либо тянут старые layout-паттерны.
Нужен один окончательный вариант.

9. Заказы — список

Выбранный заказ либо показывает compact preview справа, либо открывает detail — в зависимости от существующей логики.

14. Настройки

Но внутри каждый модуль должен использовать одинаковый pattern:

Не делать каждый справочник визуально новым приложением.
15. Light Theme
Это главный вариант для передачи клиенту.
Не чистый стерильный #ffffff везде.
Я возьму из основного сайта характер:
- warm/off-white canvas;
- белые рабочие surfaces;
- navy text;
- wine/burgundy accent;
- тонкие нейтральные borders.
Причём master-reference остаётся геометрией, а основной сайт — характером бренда.
То есть CRM не станет лендингом.
16. Связь с основным сайтом Lingvo Connect
Очень полезная часть твоего видео — участок примерно после 5 минуты.
На сайте хорошо работают:
- тёплый ivory background;
- тёмный сине-графитовый текст;
- приглушённый винный акцент;
- много воздуха;
- очень тонкие линии;
- крупная typography;
- rectangular editorial blocks;
- спокойный visual rhythm.
Сейчас CRM слишком явно выглядит как:
generic SaaS + ярко-розовый accent.

Я это скорректирую.
CRM должна ощущаться как внутренняя система того же Lingvo Connect, а не купленная сторонняя CRM, куда вставили логотип.
17. Dark Theme
На видео после переключения примерно с 3:00 видно несколько проблем.
Самая заметная:
появляются абсолютно белые горизонтальные полосы/участки внутри тёмного интерфейса.
Это происходит в таблицах/pagination/legacy surfaces.
Исправлять буду не отдельными:
background:black !important
а через semantic tokens.
Полный аудит:
- canvas;
- sidebar;
- header;
- cards;
- table;
- row;
- pagination;
- form;
- dropdown;
- select;
- combobox;
- modal;
- drawer;
- tooltip;
- file panel;
- status;
- auth;
- settings;
- empty/error/loading.
Ни одного случайного белого island в Dark.
18. Цвет Dark Theme

19. Motion / EFX
Сейчас CRM практически статична.
Для MVP добавлю очень лёгкий premium-feel.
Будут
Page content entrance:
opacity + translateY 4–8px
Card hover:
очень лёгкий lift/border change.
Button press:
translateY(1px) / subtle scale.
Sidebar nav:
мягкий active transition.
Dropdown/popover:
opacity + 4px translate.
Modal/drawer:
fade/slide.
Table row:
subtle highlight.
Selected row → detail:
связанный визуальный transition.
Toast:
slide/fade.
Pipeline:
мягкое переключение текущего статуса.
Skeleton/loading:
спокойный shimmer только там, где полезен.
Не будет
- bouncing;
- glow everywhere;
- бесконечных gradients;
- floating UI;
- gaming effects;
- анимации ради анимации.
В CRM пользователь должен через десять минут перестать замечать анимацию, но продолжать чувствовать отзывчивость интерфейса.
И обязательно:
@media (prefers-reduced-motion: reduce)

21. Mobile
На мобильном не пытаемся повторить desktop 1:1.
Sidebar → drawer.
Tables → либо controlled horizontal table, либо stacked rows в зависимости от данных.
Detail panel → full-screen/drawer.
KPI → 1–2 колонки.
Actions → compact/sticky where useful.
Touch target минимум нормального размера.

И ещё важный вывод после разбора ролика: направление master-reference менять не надо. Проблема сейчас не в том, что сам выбранный дизайн плохой. Проблема в том, что v3 реализовал его примерно на 50–60%: shell и Dashboard приблизились, а остальная CRM в значительной степени осталась старой системой под новым CSS.
Следующий проход я поэтому буду делать не как «v3.1 — поправить цвета», а как настоящий frontend consolidation pass: одна сетка, одна design system, реальные пересобранные экраны и затем полноценный QA до состояния клиентского MVP.
