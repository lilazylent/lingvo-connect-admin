# План реализации после Phase 0

## Правило перехода

Этот документ — план, а не разрешение начать разработку. Phase 1 стартует только после отдельного подтверждения владельца и ответов на блокирующие вопросы.

## Phase 1 — фундамент и безопасный вход

**Результат:** воспроизводимая локальная среда, пустая защищенная оболочка админ-панели.

- создать Next.js и FastAPI приложения в зарезервированных каталогах;
- поднять PostgreSQL через Docker Compose;
- настроить SQLAlchemy/Alembic и первую миграцию пользователей/сессий/аудита;
- реализовать вход, выход, отзыв сессий и роли;
- создать оболочку, навигацию, error boundaries, health checks;
- генерировать TypeScript-клиент из OpenAPI;
- добавить CI-проверки локального проекта без публикации.

**Gate:** ответы Q01–Q05, threat review, тесты cookies/CSRF/rate limit, миграция up/down на чистой базе.

## Phase 2 — входящие заявки

**Результат:** публичная заявка безопасно появляется в рабочем списке.

**Статус реализации:** завершено в локальной ветке `codex/phase2-applications`. Совместимый public endpoint, operational workspace, ручное создание, comments, controlled local files, activity и real-data dashboard реализованы. Расширенные Clients/Orders не начаты.

- миграции `applications` и справочника статусов;
- совместимые `POST /api/public/leads` и `/api/public/leads/with-attachment` с контрактными тестами;
- список, фильтры, поиск, карточка, ответственный, внутреннее резюме;
- серверная пагинация и аудит;
- скрипт пробной миграции существующих Leads с dry-run;
- минимально переключить транспорт публичной формы в отдельной local integration branch без изменения дизайна, контента, SEO и navigation.

**Gate:** ответы по статусам; сравнение нового и действующего OpenAPI; тест дубля/idempotency; сверка тестовой миграции.

## Phase 3 — клиенты, заказы и позиции

**Результат:** менеджер конвертирует заявку или вручную создает полноценный многоуслуговый заказ.

- компании, контакты, заказы, позиции, профиль письменного перевода;
- атомарная конвертация заявки;
- ручное создание и редактирование;
- статусы, сроки, архивирование, optimistic concurrency;
- карточка заказа и единая история действий;
- импорт выбранных строк Google-таблицы в тестовом режиме.

**Gate:** Q06–Q16; приемочные сценарии с одним и несколькими видами услуг; отсутствие тихого объединения клиентов.

## Phase 4 — переводчики, тарифы и финансы

**Результат:** назначения и воспроизводимый расчет без переписывания исторических цен.

- справочник переводчиков и языковых пар;
- назначения на позиции заказа;
- тарифы с неизменяемыми версиями;
- pricing snapshot и финансовая часть заказа;
- матрица доступа к ставкам и оплате;
- валидация валют, единиц и коэффициентов.

**Gate:** Q17–Q24 и утвержденные тестовые примеры расчетов с ожидаемыми результатами.

## Phase 5 — файлы и совместная работа

**Результат:** защищенная работа с документами и комментариями.

- выбрать storage и политику хранения;
- загрузка, проверка типа/размера/вируса, приватное скачивание;
- файлы заявки, заказа и позиции;
- комментарии, редактирование с аудитом, архивирование;
- при отдельном решении — добавить вложения в публичную форму и обновить оба контракта.

**Gate:** Q25–Q27, security review, тест несанкционированного доступа, проверенное восстановление storage.

## Phase 6 — операционный обзор и запуск

**Результат:** рабочий MVP с контролируемым переключением источника заявок.

- дашборд: новые заявки, активные заказы, просроченные/ближайшие сроки;
- доступность, keyboard flow, адаптивность и производительность;
- резервные копии, логи, мониторинг и runbook;
- генеральная миграция в тестовой среде;
- короткое окно freeze, финальная миграция, переключение public API URL;
- smoke test реальной заявки и план отката.

**Gate:** Q28–Q30, sign-off клиента, успешные backup/restore и rehearsal cutover.

## После MVP

Только по отдельному решению:

- кабинет переводчика;
- расширенная CRM/HRM и учет договоров;
- автоматическое планирование загрузки;
- уведомления и интеграции с мессенджерами/почтой;
- аналитика выручки и маржинальности;
- полноценный импорт/экспорт бухгалтерских данных;
- дополнительные роли и тонкая матрица прав.

## Стратегия тестирования

На каждом этапе обязательны:

- unit-тесты бизнес-правил и прав доступа;
- API integration-тесты с реальным PostgreSQL;
- миграции на пустой и наполненной копии базы;
- E2E для критичного пользовательского flow;
- проверка клавиатуры и базовой доступности;
- тесты пагинации, конкурирующих изменений и повторной отправки;
- скан секретов и зависимостей;
- ручная приемка владельцем до следующего этапа.

## Git и выпуск

- Разработка ведется только в отдельном `lingvo-connect-admin`.
- На Phase 0 remote отсутствует; создание GitHub-репозитория и push запрещены до прямого разрешения.
- Когда remote будет разрешен, крупные этапы выполняются в ветках `codex/...` с небольшими осмысленными коммитами.
- Опубликованная история не переписывается и force-push не используется.
- Публичный `lingvo-connect` меняется только отдельным согласованным коммитом в момент интеграции.

## Definition of ready для Phase 1

- владелец утвердил [ADMIN-MVP-SCOPE.md](./ADMIN-MVP-SCOPE.md);
- получены ответы Q01–Q05 из [OPEN-QUESTIONS.md](./OPEN-QUESTIONS.md);
- подтверждены роли и начальные пользователи;
- утверждено, что локальный каркас можно реализовывать;
- отдельно определено, можно ли создавать remote. Без такого разрешения работа остается локальной.
