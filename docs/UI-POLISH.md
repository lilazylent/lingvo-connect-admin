# Уточнение рабочего интерфейса — 6 сентября 2026

Ветка: `codex/admin-workspace-polish`. Публичный сайт и backend не изменялись.

## Что реализовано

- Карточка заявки разделена на контакт, исходное обращение, рабочие данные и совместную работу. Видны источник обращения, ответственный и состояние сохранения.
- Компания в заявке обозначена именно как текстовое поле, а не связанный справочник. Раздел «Клиенты» объясняет будущую связь компания → представитель → заказ; незапущенные разделы помечены «Позже».
- Поиск отделён от дополнительных фильтров. На узких экранах таблица превращается в подписанные записи; переход в заявку доступен настоящей ссылкой с клавиатуры.
- Единый Select на Base UI заменяет браузерные списки в существующих формах. Выбор, наведение, фокус и ошибка имеют разные состояния. Поддержаны Escape, клавиатура, отключённые варианты и reduced motion.
- Локальный Onest, согласованные размеры текста, отступы, поверхности и состояния полей. Навыки design-system, ux-copy и accessibility-review использованы для согласования компонентов, объяснения происхождения данных и проверки состояний.
- Комментарий/загрузка файла больше не сбрасывают несохранённые рабочие поля. Ошибки FastAPI 422 отображаются текстом вместо попытки вывести массив объектов в React.

## Проверено

- lint, typecheck, production build — успешно.
- Backend pytest — 22 теста успешно; есть предупреждения о будущей deprecation в зависимостях.
- Playwright — 11 тестов успешно: выбор, Escape/клавиатура, фильтры, ручное создание (контракт запроса), сохранение и комментарии, смена статуса, обработка 422.
- Браузерные проверки ширин 1920, 1440, 1024, 768, 390, 375: список, карточка, клиенты, форма создания и popup. Сняты screenshots, проверены отсутствие горизонтального переполнения и ошибок pageerror. Отдельно просмотрены desktop-карточка, mobile-список и mobile-select.
- Найденное на 1024 переполнение от абсолютно позиционированной подписи таблицы исправлено. Подсказки полей отделены от доступного имени input.

## Границы проверки и следующий этап

Docker engine был недоступен. Браузерные тесты используют изолированные перехваты API с вымышленными данными только в `e2e/`; приложение не содержит demo-login или обхода авторизации. Это не проверка живой PostgreSQL-интеграции. После запуска Docker нужно отдельно проверить реальную авторизованную сессию, создание заявки и сохранение в БД.

Клиентское ТЗ `02-future-admin-dashboard-spec.md` шире этого UI-прохода. Справочники компаний/представителей, полный цикл заказов и расчёт тарифов ещё не реализованы. Следующий функциональный этап должен дать устойчивые связи по ID, API и миграции, а не имитацию карточек на frontend. Формулы расчёта, статусы и обязательные поля требуют фиксации по ТЗ.

Запуск UI-тестов: `cd apps/admin-web`, `npm run test:e2e`. На Windows используется установленный Edge, на других ОС нужен браузер Playwright. Скриншоты находятся в игнорируемом `test-results/`. У репозитория не настроен remote; push не выполнялся.
